cft-rebound — dossier
=====================

I. What it is

REBOUND's IAS15 integrator with its arithmetic routed through libcft, the IEEE 754-2019 binary32/64/128/256 library of the cft-fp256 project, so that the same integrator runs at binary64, binary128 and binary256 - and, given an artifact, on the FP256 tile - with the same bits everywhere [fact 1760].

II. What it is not

The README carries no “what it is not” heading. Its nearest equivalent is “Scope: what it integrates, and what it refuses [fact 1761]”, a refusal list rather than a limits statement. In the README's own words: “Everything below is refused, by name, with a message - never silently ignored, never approximated [fact 1762]. The list is one table in code (cft_support_rows, src/cft_supported.c) that both entry points walk, and the gate walks it too and fails on any row no case exercises [fact 1763]”

- this is direct summation. REB_GRAVITY_COMPENSATED is refused too: a different summation from the one ported [fact 1764]
- WHFast is ranked first to follow (docs/INTEGRATORS.md) and has not been done [fact 1765]
- a heap overread in REBOUND's own gravity loop. There is no bit-identity to claim against undefined behaviour [fact 1766]

III. The contract

At binary64 it is REBOUND's own IAS15 bit for bit, which is a gate the port passes on every build [fact 1767].

V. Kept failures

- REBOUND's IAS15 was thought to leave a *stale polynomial* behind when a particle is removed [fact 1772]. So the polynomial is not stale. It is aliased, and the survivors do not inherit each other's coefficients - they inherit fragments of the level above [fact 1773] — 2026-09-11 [fact 1774], 30. Collisions, and a defect that was not the one we wrote down [fact 1775]. Fixed by commit 1561d35 [fact 1776].
- A banner is the only place in this suite that states a step count without executing it, so under --light it was the only place that could overstate the work done [fact 1777] — 2026-09-11 [fact 1778], 33. --light, and the banner that overstated it [fact 1779]. Fixed by commit e12aed9 [fact 1780].

VI. Test it

- make check-quick: cheaper arguments + the gate cache [fact 1781], 5 s warm [fact 1782].
- make check-light: cheaper arguments, the cache, and step counts scaled down [fact 1783], ~9 min [fact 1784].
- make check: every gate at every format, never skipping one [fact 1785], ~55–70 min [fact 1786].

VII. Prove it wrong

Cheapest first; the site-wide rules of engagement are stated once, on the Corrections page.

- make check-quick on a clean clone, and see whether the cache lets anything silently pass: Every skip prints itself by name [fact 1787].
- make check-light end to end, and compare it against make check on the same commit: a scaled leg that disagrees with the full one is a disproof.
- Point CFT_REBOUND_ARTIFACT at the software backend and at a card image on the same problem and diff every coordinate: the contract is bit identity at binary64, not agreement within a tolerance.
- Run make check itself, which executes [fact 1788], and read the log rather than the exit code.
