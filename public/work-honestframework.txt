HonestFramework — dossier
=========================

I. What it is

A way to lay out a project so that an AI can write nearly all of it and no claim about it ever rests on the AI's judgement [fact 2151].

II. What it is not

- Not a prompting guide. Nothing here depends on phrasing, model, or version. The mechanisms are files and exit codes [fact 2152]
- Not a substitute for tests. It is a set of properties your tests and build must have before their green means anything [fact 2153]
- Not free. A project built this way carries a reference implementation it could have done without, a second copy of some checks, and a ledger that only grows [fact 2154]
- Not about distrusting the agent. The agent in the case study wrote essentially all of 743,605 lines across six repositories, including every mechanism described here, and found most of the defects listed in it [fact 2155]

III. The contract

That is the whole thesis in one example [fact 2156]. The agent wrote every line of the fix [fact 2157]. It decided nothing about whether the fix worked [fact 2158].

IV. Verified

No docs/VALIDATION.md ledger: HonestFramework is a document, not a build. What it records instead is its own tools/check_claims.py [fact 2159], which holds facts about itself equal on every run. Re-read here from the pin, not by running that script against a checkout:

- METHOD.md's numbered mechanisms: 10 [fact 2149], agreeing with the word README.md states for them.
- CASE-STUDY.md's per-repository table sums to 743,605 [fact 2150] tracked lines, agreeing with the headline both documents quote.

VI. Test it

- python tools/check_claims.py: This repo's own gate [fact 2170] — links, the mechanism count and the case-study total are among what it re-checks.
- Recompute CASE-STUDY.md's per-repository table by hand: the same arithmetic 743,605 [fact 2150] already shows, done again with nothing but the table.

VII. Prove it wrong

Cheapest first; the site-wide rules of engagement are stated once, on the Corrections page.

- python tools/check_claims.py on a clone, and see whether it still finds nothing.
- Add up CASE-STUDY.md's per-repository table yourself; a sum that disagrees with the quoted headline is a disproof the script would also catch.
- Pick one of the load-bearing quotations the audit re-verified and fetch its named source yourself: the method's own rule is that a citation is checked by fetching, not by plausibility.
- Re-audit the claim-source controls in atlas-darkroom's external-sources programme against their named sources; that repository is private for now, so this is the one item here this dossier cannot hand you a path to.
