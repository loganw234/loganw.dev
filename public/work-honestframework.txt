HonestFramework — dossier
=========================

I. What it is

A way to lay out a project so that an AI can write nearly all of it and no claim about it ever rests on the AI's judgement [fact 1388].

II. What it is not

- Not a prompting guide. Nothing here depends on phrasing, model, or version. The mechanisms are files and exit codes [fact 1389]
- Not a substitute for tests. It is a set of properties your tests and build must have before their green means anything [fact 1390]
- Not free. A project built this way carries a reference implementation it could have done without, a second copy of some checks, and a ledger that only grows [fact 1391]
- Not about distrusting the agent. The agent in the case study wrote essentially all of 743,605 lines across six repositories, including every mechanism described here, and found most of the defects listed in it [fact 1392]

III. The contract

That is the whole thesis in one example [fact 1393]. The agent wrote every line of the fix [fact 1394]. It decided nothing about whether the fix worked [fact 1395].

IV. Verified

No docs/VALIDATION.md ledger: HonestFramework is a document, not a build. What it records instead is its own tools/check_claims.py [fact 1396], which holds facts about itself equal on every run. Re-read here from the pin, not by running that script against a checkout:

- METHOD.md's numbered mechanisms: 10 [fact 1386], agreeing with the word README.md states for them.
