cft-fp256 — dossier
===================

I. What it is

A math coprocessor that gets the same answer everywhere [fact 1987]. It does IEEE 754 arithmetic at four precisions - 32, 64, 128 and 256 bits - and guarantees that the same inputs give the same bits whether the work runs on a laptop CPU, in a browser tab, on a microcontroller, or on the FPGA card it was designed for [fact 1988].

II. What it is not

Raw fp32 and fp64 throughput [fact 1989]. Every CPU and GPU on the market serves those formats at clocks and lane counts an FPGA fabric will not match, and nothing here pretends otherwise [fact 1990]. The tile earns its place at the precisions commodity hardware does not offer, and on the guarantee that the answer does not move [fact 1991].

III. The contract

Named levels, quoted from CONFORMANCE.md: “Level A - IEEE 754-2019 in radix 2 [fact 1992]” is the standard itself; “Level B - the cft-fp256 profile [fact 1993]” is “Level A, plus every choice the standard leaves to the implementation fixed to one answer, plus operations the standard does not define [fact 1994].” The relationship runs one way, in the document's own words: “An implementation conforming to the cft-fp256 profile conforms to [fact 1995] IEEE 754-2019 in radix 2 for the operations the profile covers [fact 1996].”

The README states the promise directly: “That guarantee is the product [fact 1997].” The hardware only makes it faster [fact 1998].

The contract is versioned. CONFORMANCE.md opens with its profile, “Profile 3.1, 2026-10-13 [fact 1999]” (profile 3 was 2026-10-05, profile 2 2026-10-02 and profile 1 2026-09-16 [fact 2000]), and says of the tree: “a minor step: cases added, none moved [fact 2001].” A minor step is “an addition that changes no recorded case and no accepted image [fact 2002].”

V. Kept failures

- cocotb's inability to set an exit code — stated in its own makefile at Makefile.inc:88, which checks only that the file *exists* — meant three real RTL failures were reported as a pass [fact 2008]. Fixed by the entry 2026-09-12 - two gates that could not fail, and the path that has always been the critical one [fact 2009], commit f192bf0 [fact 2010].
- a device predating a new capability flag ignored an unchecked reserved bit and read far past a one-element buffer [fact 2011] — measured as a host-side segfault in the entry 2026-09-12 - a stride-0 operand, the MODE guard it needed, and a contract I misread [fact 2012]. Fixed by commit 8b7dea1 [fact 2013].
- exp2 at x = emin - p [fact 2014]: Its exact value 2^(emin - p) is half the smallest subnormal, the tie between +0 and it, which IEEE 754's roundTiesToAway (rmm) rounds to the subnormal. The model rounded it as a quarter of the subnormal and gave +0 [fact 2015]. Step 6's design study M1 found it (its question 5), verifier-VM1 confirmed it [fact 2016] — in the entry 2026-10-05 - the golden model's exp2 tie fixed, and the conformance profile's major step to 3 (parcel XT); M1's design study merged as a design record [fact 2017]. Fixed by commit ca43695 [fact 2018].

VII. Prove it wrong

Cheapest first; the site-wide rules of engagement are stated once, on the Corrections page.

- Open the web page above and hand it your own vector file: “Drop a vector file on it and it scores itself [fact 2025].” Anything less than a perfect score is a disproof.
- make vectors locally, then compare the digests it writes with the ones the repository publishes in vectors/SHA256SUMS [fact 2026], by the recipe CONFORMANCE.md gives; a differing line is a disproof. The record says this is a check no gate makes: “no gate compares a set's digest with vectors/SHA256SUMS [fact 2027].”
- Replay the identity protocol yourself in another language and compare its checksum line against the ones docs/COMPATIBILITY.md [fact 2028] records; a differing hex value is a disproof.
- Rebuild host/tools/mpfr_check.c and widen its sweep past the campaign's own cases: the independent oracle is only as good as the cases put to it. The record names one it lacks: “The MPFR campaign's pool (host/tools/mpfr_check.c, build_tpool) lacks the tie's argument, so the gate's mpfr stage does not test the fix; XT-1's probe does [fact 2029].”
