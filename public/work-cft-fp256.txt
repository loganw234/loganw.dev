cft-fp256 — dossier
===================

I. What it is

A math coprocessor that gets the same answer everywhere [fact 297]. It does IEEE 754 arithmetic at four precisions - 32, 64, 128 and 256 bits - and guarantees that the same inputs give the same bits whether the work runs on a laptop CPU, in a browser tab, on a microcontroller, or on the FPGA card it was designed for [fact 298].

II. What it is not

Raw fp32 and fp64 throughput [fact 299]. Every CPU and GPU on the market serves those formats at clocks and lane counts an FPGA fabric will not match, and nothing here pretends otherwise [fact 300]. The tile earns its place at the precisions commodity hardware does not offer, and on the guarantee that the answer does not move [fact 301].

III. The contract

Named levels, quoted from CONFORMANCE.md: “Level A - IEEE 754-2019 in radix 2 [fact 302]” is the standard itself; “Level B - the cft-fp256 profile [fact 303]” is that plus every choice the standard leaves open, fixed to one answer. The relationship runs one way, in the document's own words: “An implementation conforming to the cft-fp256 profile conforms to [fact 304] IEEE 754-2019 in radix 2 for the operations the profile covers [fact 305].”

The README states the promise directly: “That guarantee is the product [fact 306].” The hardware only makes it faster [fact 307].

V. Kept failures

- cocotb's inability to set an exit code — stated in its own makefile at Makefile.inc:88, which checks only that the file *exists* — meant three real RTL failures were reported as a pass [fact 311]. Fixed by the entry 2026-09-12 - two gates that could not fail, and the path that has always been the critical one [fact 312], commit f192bf0 [fact 313].
- a device predating a new capability flag ignored an unchecked reserved bit and read far past a one-element buffer [fact 314] — measured as a host-side segfault in the entry 2026-09-12 - a stride-0 operand, the MODE guard it needed, and a contract I misread [fact 315]. Fixed by commit 8b7dea1 [fact 316].

VI. Test it

- replays the published conformance vectors in front of you [fact 318] — a browser tab, nothing installed.
- make golden: The golden model's self-tests [fact 319] (needs only Python and, optionally, mpmath).
- the card: compares a device against the software backend bit for bit across the elementwise operations [fact 320], which needs the FPGA and its toolchain.

VII. Prove it wrong

Cheapest first; the site-wide rules of engagement are stated once, on the Corrections page — not yet built, so this dossier does not link it.

- Open the web page above and hand it your own vector file: “Drop a vector file on it and it scores itself [fact 321].” Anything less than a perfect score is a disproof.
- make golden locally, against the same vector sets published in the repository's vectors/SHA256SUMS [fact 322].
- Replay the identity protocol yourself in another language and compare its checksum line against the ones docs/COMPATIBILITY.md [fact 323] records; a differing hex value is a disproof.
- Rebuild host/tools/mpfr_check.c and widen its sweep past the campaign's own cases: the independent oracle is only as good as the cases put to it.
