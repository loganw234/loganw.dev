IWhat it is

A method for splitting one body of work across several coding agents at once, without the pieces failing to meet (ParcelRound f42242e README.md:3).

IIWhat it is not

Under “Is this for you? (ParcelRound f42242e README.md:31)”: “Don't” for a single task, for exploratory work where the split isn't obvious yet, or where the pieces can't be tested separately (ParcelRound f42242e README.md:37). Two agents on a two-way split is usually slower than doing it yourself, because the brief costs more than the work (ParcelRound f42242e README.md:38).

IIIThe contract

Under “The one failure mode (ParcelRound f42242e METHOD.md:40)”: the work between the parcels belongs to nobody, and it is invisible because every parcel's own gate is green (ParcelRound f42242e METHOD.md:43). Of its own rules it says: “Every rule here is here because something broke without it, or because its practice caught a defect before it shipped, or, where the rule says so, because it rests on practice that held, on a cost, or on the owner's word (ParcelRound f42242e METHOD.md:3).”

VITest it

  1. python tools/check_method.py: “The front door: python tools/check_method.py says whether the method still holds together (ParcelRound f42242e README.md:29).” Its docstring adds: “There is no cache: each run reads everything again (ParcelRound f42242e tools/check_method.py:90).”
  2. python tools/check_method.py --control: “--control shows each of its checks can fail (ParcelRound f42242e README.md:29)”; in its docstring's words, it will “plant faults, each in a copy of the tree or in a scratch repository, at least one per check; each must be caught (ParcelRound f42242e tools/check_method.py:5).”
  3. Read CASE-STUDY.md's worked example yourself and check that its account holds together — free, and README.md calls it “The clearest single argument for it (ParcelRound f42242e README.md:68).”
  4. Compare templates/brief.md and templates/verifier.md with METHOD.md: ADOPTION.md says “Each rule in a template is tagged, in parentheses, with the METHOD.md section it comes from, or "own" for the templates' own guidance, as each template's legend says (ParcelRound f42242e ADOPTION.md:44),” so follow a tag, and read the section it names.
  5. Try the step the method takes before any split, on a codebase you already know: list every file each of several independent changes would touch, and see whether one file appears in several such lists at once.

VIIProve it wrong

Cheapest first; the site-wide rules of engagement are stated once, on the Corrections page.

  1. Build a fault the gate's threat model covers, in a copy of the tree, and run python tools/check_method.py. Its docstring claims: “Inside the threat model, the gate must catch it or a limit below must state it (ParcelRound f42242e tools/check_method.py:31).” A fault inside the model that passes, with no stated limit covering it, is a disproof.
  2. Pick a row of ADOPTION.md marked adopted, or a line of a template tagged with a section, and read the METHOD.md section it names. The gate states what it cannot see there: “it holds that an adopted row's headings exist, not that the rule is under them (ParcelRound f42242e tools/check_method.py:145),” and “It holds that a section named exists, not that it holds the rule the line beside it claims (ParcelRound f42242e tools/check_method.py:157).” A section that does not hold the rule is a disproof.
  3. Check the sources of the timeline in CASE-STUDY-6.md (ParcelRound f42242e). Its heading says “from the ledger's own timestamps, and from the commits' times where a row says so (ParcelRound f42242e CASE-STUDY-6.md:51).” Compare a row that says so with the times of the commits it describes, and any other row with the stamp of the ledger entry it comes from. A row that disagrees with its source is a disproof.
  4. Recount the sixth round against the ledger its case study archives: “The ledger is archived beside this file as archive/round6-ledger.zip (ParcelRound f42242e CASE-STUDY-6.md:4).” The figures Verified quotes from that case study are counts a recount can disagree with; a count the archived ledger does not bear out is a disproof.
  5. Apply the method to a real, multi-agent piece of work of your own and see whether the one failure mode still finds something the briefs missed; a clean round is evidence against the method's reach, not proof it is wrong, since “found nothing” is a stated, acceptable result here too.
